# Releasing Bookworms for iPhone and Mac

This checklist covers what a TestFlight or App Store build of the iPhone and Mac app needs beyond a passing local build. The app's one multiplatform target signs both platforms with the bundle ID `gay.ian.Bookworms.iOS` (`project.yml`), so the iPhone and Mac versions share one App Store listing as a universal purchase. That listing is separate from the Apple TV app's, `gay.ian.Bookworms`. A shipped bundle ID can't change.

## App Store Connect record

1. **New app.** In App Store Connect → **Apps** → **+** → **New App**, select the **iOS** and **macOS** platforms, the bundle ID `gay.ian.Bookworms.iOS`, primary language English, and a unique internal SKU, such as `bookworms-ios`. Give the app its own name: App Store names are unique, and the Apple TV listing uses `Bookworms - eBook Display`. Accept any pending developer agreements.
2. **App information.** Choose **Books** as the primary category. Copy the privacy policy URL, support and marketing URL, contact, and price from the App Store information table in the tvOS release workflow. Under content rights, say that the app shows third-party content: Hardcover metadata, covers, profile photos, and ratings.
3. **Age rating.** Answer the user-generated content questions as the Apple TV listing does. The app shows other Hardcover readers' profiles, photos, and ratings.
4. **Availability.** Match the Apple TV listing: every current storefront except **China mainland**, which requires an NPPA internet publishing permit for apps with book content, and automatic availability in future storefronts off. Follow the public storefront availability steps in the tvOS release workflow.

## Before the first TestFlight build

1. **Private Cloud Compute capability.** Apple granted the team the managed `com.apple.developer.private-cloud-compute` entitlement on 2026-10-27. Confirm that Private Cloud Compute is on in Certificates, Identifiers & Profiles for each App ID that signs a build: `gay.ian.Bookworms.iOS`, which the iPhone and Mac archives sign with, and `gay.ian.Bookworms.Mac`, which `script/run_mac.sh` signs development Mac builds with. Signing a build with the entitlement fails until its provisioning profile includes it. `script/install_on_device.sh` and `script/run_mac.sh` build with Private Cloud Compute by default and say what to do when the profile lacks it. Their `--no-pcc` option builds a test-only variant without it (`NO_PCC`) that designs with the reader's provider and API key, the on-device model, or local defaults, and never names Private Cloud Compute; never archive that variant for TestFlight.
2. **Distribution entitlements.** The App ID `gay.ian.Bookworms.iOS` needs iCloud with the CloudKit container `iCloud.gay.ian.Bookworms`, Push Notifications, and Private Cloud Compute, so that its iOS and macOS App Store distribution profiles include them. `Bookworms/Bookworms.entitlements` and `Bookworms/Bookworms-macOS.entitlements` set the push environment to `development` and name no iCloud environment; distribution signing sets both to production. No test checks that, so after you export both archives (step 5 of **Before each archive**), run `script/release.sh check <candidate folder>`. It prints the entitlements of the exported iPhone `.ipa` and of the app in the Mac `.pkg`, then each bundle's version and build, bundle ID, privacy manifest and its declared reasons, LLVM coverage section count, architectures, example profile, signing authority, and signature verification.

   Upload a build only when its output has every value in its column:

   | Entitlement | iPhone `.ipa` | Mac `.pkg` |
   | --- | --- | --- |
   | Push environment | `aps-environment` is `production` | `com.apple.developer.aps-environment` is `production` |
   | `com.apple.developer.icloud-container-identifiers` | `iCloud.gay.ian.Bookworms` | `iCloud.gay.ian.Bookworms` |
   | `com.apple.developer.icloud-services` | `CloudKit` | `CloudKit` |
   | `com.apple.developer.icloud-container-environment` | `Production` | `Production` |
   | `com.apple.developer.private-cloud-compute` | `true` | `true` |
   | `com.apple.security.app-sandbox` | Absent | `true` |
   | `com.apple.security.network.client`, `com.apple.security.personal-information.photos-library`, and `com.apple.security.files.user-selected.read-write` | Absent | `true` |

3. **CloudKit production schema.** Production has the `SpineWorklistV1`, `SpineDesignV1`, `CoverChoiceV1`, `SeriesLookV1`, `SeriesLinkV1`, `TopFivePinsV1`, and `SpineClaimV1` record types, each with a `payload` field of type Bytes. Without `SpineClaimV1`, runs still design every book, but two devices that run at once may each send a request for the same book. The app also writes the `LibraryArchive` record type, whose `archive` asset field the Apple TV app's release workflow already requires in Production; confirm it is there, or every library upload fails and each device downloads from Hardcover on its own.
4. **Apple TV build.** Apple TV 1.2.0 and later include the companion-designs and series-look work: they publish `SpineWorklistV1`, draw `SpineDesignV1` designs on Book Wall, show covers chosen in `CoverChoiceV1`, apply `SeriesLinkV1` choices, and create and draw `SeriesLookV1` looks (see `README-AI.md`'s [iCloud contract](../README-AI.md#icloud-contract)). They also include the shared-library work, which reads `library-v1` before a due Hardcover fetch, keeps each book's covers fixed by the same rule as this app, and keeps `review`, `editionFormat`, and `seriesMemberships`. Keep that work in every later Apple TV build. Apple TV 1.1.0 and earlier ignore the designs, looks, and choices, fetch on their own schedule, and drop `review` from every snapshot when they upload. Their covers can differ from this app's after the reader changes an edition, so some designs that a signed-in iPhone makes for its own copy may not match those books on that Apple TV. Books from the snapshots of an Apple TV build that doesn't download `seriesMemberships` group by their featured series.
5. **Privacy manifest.** Confirm that each archived `Bookworms.app` contains `PrivacyInfo.xcprivacy`, at the bundle's root on iPhone and in `Contents/Resources` on Mac (`script/release.sh check` prints it), and that each archive's privacy report (Organizer, **Generate Privacy Report**) shows only the declared UserDefaults (CA92.1) and file timestamp (C617.1) reasons. The Keychain needs no declared reason.
6. **App Privacy answers.** Ian decides these answers. The recommended answer for both platforms is **Data Not Collected**, as for the Apple TV app in the tvOS release workflow, because the developer receives none of the data the app sends:
   - **Hardcover.** The app sends the reader's Hardcover tokens only to Hardcover. It reads the reader's own library and block list, and the public profiles, names, photo links, ratings, and finish dates of the readers the account follows or looks up. The friends' data (`social-snapshot.json`) and the image cache, which holds their profile photos, stay on the device, and signing out deletes both. **With friends**, **My reading**, and **Share desk** images carry the reader's Hardcover username and profile link only when the reader shares them; **My reading** and **Share desk** images also show it in the preview, and leave it out when the reader turns off **Show profile link**.
   - **iCloud.** The library, with the reader's reviews, is cached on the device. While the device is signed in to iCloud and iCloud storage is on, which it is unless the reader turned it off, the app also saves the library to the reader's private iCloud database, as the account's snapshot in `library-v1`, where the reader's other Apple devices use it. Designs, series looks, cover choices, series choices, Top Five pins, and the worklist go to the same database. When iCloud already holds Bookworms data from another Hardcover account, the app reads and writes nothing in iCloud until the reader chooses **Merge** or **Keep iCloud Off**. After **Keep iCloud Off**, the device uses no iCloud data until the reader chooses **Turn on iCloud storage** in the Hardcover sheet or, on the Mac, in **Settings > Hardcover** (see `README-AI.md`'s [One Hardcover account in iCloud](../README-AI.md#one-hardcover-account-in-icloud)). Signing out of Hardcover deletes the device's copy and leaves the iCloud copy, which the signed-out app still shows while iCloud storage is on. The developer can't read the iCloud database.
   - **Spine design models.** Private Cloud Compute is Apple's service, and Apple's on-device model designs on the device. A third-party provider, Anthropic, OpenAI, Google Gemini, or an OpenAI-compatible endpoint, receives each book's cover, title, and author, and the text Vision read on the cover, only after the reader sets it up with their own account and API key. The first time the reader saves an API key for a third-party provider on a device, the app asks once, and the provider receives book data only after the reader selects **Allow**. Every request checks that answer, so a key that the Keychain kept from an earlier install sends nothing until the reader allows its provider again. The developer runs no server between the app and any of them.
   - **Fonts and covers.** Google Fonts and the cover hosts receive standard connection information.
   - **Camera.** **View in my room**, on iPhone only, uses the camera on the device. Camera frames and the scene mesh are never stored or uploaded, and the photo goes only where the reader shares it.
   - **Example profile.** It reads data bundled in the app, saves nothing, and makes no request besides the cover and font downloads any library makes.
7. **Privacy policy.** One policy covers Bookworms on Apple TV, iPhone, and Mac. It is published at https://ian.gay/bookworms-privacy-policy/, the privacy policy URL of this listing and of TestFlight's test information. Its text lives in the tvOS release workflow (`docs/RELEASING.md` in the tvos repository, **Privacy policy text**), and the web page and the Apple TV listing's **Apple TV Privacy Policy** field must carry the same text and effective date. When this app starts to send data somewhere new, or its iCloud, sharing, or model behavior changes, change that text first, then publish the page and paste the field in the same change, with a new effective date. Before each submission, the owner confirms that the page and the field match that text.

## Before each archive

1. **Third-party consent.** Confirm that `main` includes the consent alert (`SpineDesigner.hasConsent(of:)`) and that every provider request checks the reader's answer (`SpineDesigner.requestKey(loadKey:)`). The App Privacy answer and the review notes depend on both; don't archive a candidate without them.
2. **Version.** Set `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml`, which both platforms share. Each upload needs a build number greater than every earlier upload's, TestFlight uploads included. Run `xcodegen generate --spec project.yml` and merge both changes to `main` before you check out the candidate.
3. **Clean checkout.** Archive from a clean checkout of `origin/main`, not from a working folder with local edits or without the latest merged work: for example, run `git fetch origin`, then `git worktree add --detach <folder> origin/main`. Record the commit (`git rev-parse HEAD`) with the candidate builds.
4. **Example profile.** Open the signed-in Mac app so its launch cache is current, then run `python3 -I script/export-example-profile.py --out ExampleProfile` in that checkout. It keeps the Read books finished since 2024, prints only counts, and writes the owner's private reading data into the Git-ignored `ExampleProfile/` (see `README-AI.md`'s [Example profile](../README-AI.md#example-profile)). An archive fails with "ExampleProfile/ is missing" until the folder has `library-v1.json`; other Release builds only warn. Export again before each release, so the shipped snapshot stays recent; the app treats its sync date as today in time filters. Data in a shipped build can't be recalled; removing a book reaches only later builds.
5. **Archive and upload.** In that checkout, create a candidate folder under the Git-ignored `.local/releases/`, such as `.local/releases/1.0.0-10`, and run:

   ```sh
   . ~/.appstoreconnect/bookworms.env
   script/release.sh archive .local/releases/1.0.0-10 iOS
   script/release.sh archive .local/releases/1.0.0-10 macOS
   script/release.sh check .local/releases/1.0.0-10
   # Only after the check passes:
   script/release.sh upload .local/releases/1.0.0-10 iOS
   script/release.sh upload .local/releases/1.0.0-10 macOS
   ```

   `archive` archives the **Bookworms** scheme in Release for the platform (`Bookworms-<platform>.xcarchive`) and exports it for App Store Connect to `export-<platform>/`, a `.ipa` for iOS and a `.pkg` for macOS. Its export options (`ExportOptions-export.plist`) have the destination `export`, so it never uploads; they sign for the Production iCloud environment and keep the build number in `project.yml`. Each `xcodebuild` call writes its log to the folder (`archive-<platform>.log`, `export-<platform>.log`, `upload-<platform>.log`), and the script prints the exit status and the log's result and error lines. `check` is the entitlement check in step 2 of **Before the first TestFlight build**. `upload` exports the same archive with the same options but the destination `upload` (`ExportOptions-upload.plist`), which sends it to App Store Connect; a successful upload prints "Upload succeeded" and "EXPORT SUCCEEDED". Each platform gets its own TestFlight build. Delete the folder's `dd-archive-<platform>/` derived data after the uploads, because it is large.

   The script authenticates with the team's App Store Connect API key. `. ~/.appstoreconnect/bookworms.env` sets `ASC_KEY_PATH`, `ASC_KEY_ID`, and `ASC_ISSUER_ID` in the same shell, and the script needs all three or none. The key needs the Admin role: distribution signing with an App Manager key fails with "Cloud signing permission error". Keep the private `.p8` key outside the repository, in `~/.appstoreconnect/private_keys/`; the script refuses a key path inside the repository. Never commit the key or include it in release artifacts. A signed export with the key is verified; an upload with the key and a run with the Mac's screen locked aren't.

   Without the three variables, the script uses the account signed in to Xcode. Don't start an archive, export, or upload while the Mac's screen is locked: an `xcodebuild` archive that can't read the account's saved sign-in makes Xcode remove the account, and every later export and upload fails with "No Accounts" until the owner signs in again under **Xcode > Settings > Apple Accounts**.

## TestFlight

Each file uploaded in step 5 of **Before each archive** becomes a TestFlight build once Apple processes it. Give the builds to internal testers first, then to external testers. This repository can't see App Store Connect, so the owner confirms there everything this section says about the record, the groups, and the fields.

1. **Two builds on one record.** The iPhone and Mac archives are separate TestFlight builds on the one app record for `gay.ian.Bookworms.iOS`, listed under **iOS** and **macOS**, and each is added to a tester group on its own. The Mac build needs the record to have the macOS platform (step 1 of **App Store Connect record**).
2. **Production services.** TestFlight builds are distribution-signed, so they use the CloudKit Production environment and the production push environment, as App Store builds do; the entitlement check (step 2 of **Before the first TestFlight build**) confirms both before each upload. They need the production schema (step 3 of **Before the first TestFlight build**), they see none of the Development data that `script/install_on_device.sh` and `script/run_mac.sh` builds save, and what a tester saves to iCloud is still there in the App Store release.
3. **Test information.** Under **TestFlight > Test Information**, which the two platforms share, enter:
   - **Beta App Description**: what the app does, and that the build needs iOS 27, or macOS 27 on a Mac with Apple silicon (`deploymentTarget` and `ARCHS[sdk=macosx*]` in `project.yml`). A tester on an older system can't install it.
   - **Feedback Email**: the contact in the tvOS release workflow's App Store information table.
   - **Privacy Policy URL**: https://ian.gay/bookworms-privacy-policy/
   - **Beta App Review Information**: the owner's contact details, the Hardcover demo account that the tvOS release workflow lists for App Review, and the review notes under **App Review** with their Beta App Review ending. Enter the contact details and the demo sign-in only in App Store Connect.
4. **Internal testers.** Add both builds to an internal group, whose members are App Store Connect users on the team. Internal builds need no Beta App Review. `project.yml` declares `ITSAppUsesNonExemptEncryption: false`, so a build doesn't wait for an export compliance answer. Run the **Production cross-device check** with these builds before you invite external testers.
5. **External testers.** Add both builds to an external group. On each platform, the first build of a version that goes to external testers waits for Beta App Review, which reads the test information; later builds of the same version may not need a full review. A build stays available for 90 days.
6. **Apple TV testers.** Add the same people to the same kind of group on the Apple TV app's record, `gay.ian.Bookworms`, with a 1.2.0 or later build. The Apple TV's **Settings > Spines** sends readers to this app, so an Apple TV tester without it follows that pointer to an app they can't install.
7. **What to Test.** Each build has its own **What to Test** text. Start from this text for 1.0.0, and leave out the Apple TV item when the testers have no Apple TV build:

   ```text
   Bookworms shows your Hardcover reading library and designs a spine for each book.

   - Connect Hardcover, or choose View example profile to look around without an account.
   - Library: browse Stack and Shelf, turn 3D Books on and off, and open a book. Try Change cover, the spine's colors and font, and Redesign spine.
   - Spines: select Generate now and look at the designs as they arrive.
   - Desk: throw the books around, set up Dominoes, and share the desk as an image or a video. The desk starts with your last 12 months.
   - Share: make an image from each template, such as Top Five and Year in Books. With friends compares your ratings with the readers you follow on Hardcover.
   - With Bookworms for Apple TV on the same iCloud account and Hardcover account: turn on iCloud storage in its Settings > General and Book Wall in Settings > Views, and check that Book Wall shows your designs. Book Wall needs an Apple TV 4K (2nd generation) or later.

   Please report crashes, slow screens, and spines or images that look wrong, with the book's title.
   ```

## Screenshots

The owner chooses the library each time the listing needs screenshots: his own library or the Hardcover demo account's. Ask before you capture, and don't reuse an earlier answer.

- **Demo account.** Sign in with it on a device or simulator.
- **The owner's library.** Launch the app with his library as the preview folder (`-BookwormsPreviewFolder`; see `README-AI.md`'s [Preview with a local library](../README-AI.md#preview-with-a-local-library)). The example-profile export (`script/export-example-profile.py`) works as a preview folder and holds only his own books and designs. Capture views that show only his books, and ask him before a screenshot shows another reader. Keep the images in the ignored `.local/` folder.

Never show the Debug-only fictional reviews and friends, which sit on top of a real library.

Capture the **Share**, **Library**, **Desk**, and **Spines** tabs in the sizes that Apple's [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications) require, and check that page first, because the sizes change:

- **iPhone.** One set for the 6.1-inch or 6.3-inch display, 1179×2556 or 1206×2622 pixels in portrait, which App Store Connect uses for every iPhone size. The app runs only on iPhone (`TARGETED_DEVICE_FAMILY` in `project.yml`), so the listing needs no iPad set.
- **Mac.** A 16:10 size, such as 2880×1800, which a 1440×900-point window gives on a Retina display. Every development copy but the installed Mac app marks its windows **Test copy** (`TestCopy`), so capture the installed app, which `script/run_mac.sh --preview` launches with the library in `.local/preview`.

Apple's specifications don't allow an alpha channel, which simulator screenshots and window captures have. Remove it before you upload.

## Signed device checks

Check these on a signed iPhone with the Apple TV on the same iCloud account: the library loads; **Generate now** saves designs and continues after leaving the app; the charging task runs overnight; a worklist push schedules it; the Spines tab names **Private Cloud Compute** and shows the daily limit; and the Apple TV caches the new designs.

Check a paused run's resume on a signed iPhone and on a Mac, with a backup provider key that has a low per-minute limit, following `README-AI.md`'s [Spine generation](../README-AI.md#spine-generation): **Generate now** designs some books and then shows "Paused until" a time. With the app left open, the run starts again at that time. On the iPhone, lock the screen before that time and return to the app after it: the run starts then. **Stop** during a resumed run ends it, and the run doesn't start again at a retry time. With **Generate while charging** on, or **Generate while idle** on the Mac, a background run can still start, as after any **Stop** of a run you started.

Check the model chain on a signed iPhone, following `README-AI.md`'s [Spine design model](../README-AI.md#spine-design-model). With Apple Intelligence off and no provider chosen, the Spines tab names **Default styling** and its footer suggests turning on Apple Intelligence or choosing a provider, and a run designs spines. With a provider but no key, the tab names the next tier and says the key is missing. With the key, the tab names the provider, such as **Google Gemini with your API key**, and the info button says why Private Cloud Compute is unavailable, and with a wrong key a run moves to the next tier and says that the provider didn't accept your API key. Later runs start at that tier and show the message beside **Choose model**. **Generate now** tries the provider again, and with the wrong key still saved, the run moves to the next tier at its first book. Replacing the key clears the message, and the next run designs with the provider again. With a custom endpoint whose model takes no images, a run fails three books, then moves to the next tier with the endpoint's message. With a custom endpoint on another device on your network, not on the same Mac, and an iPhone or Mac that has never asked, the first request shows the system's Local Network alert with "Bookworms connects to the model endpoint you set up on your network to design spines.", and after **Allow** a run designs with the endpoint. After Apple Intelligence is back on, the next run gives Private Cloud Compute designs, within the daily limit, to the books that the on-device model or default styling designed, and their series' unedited looks follow; the provider's designs stay. With the provider set up and **Use this model instead of Private Cloud Compute** on, the tab names the provider while Private Cloud Compute is available, and a run designs with the provider but keeps Private Cloud Compute's designs, while **Redesign spine** on a book with a Private Cloud Compute design shows the button and redesigns it with the provider. With the switch off again, the next run designs with Private Cloud Compute and keeps the provider's designs.

Check a locked Mac on a signed Mac build with a backup model and books to design: start **Generate Now**, lock the Mac for 10 minutes, then unlock it. The run's count rose while the Mac was locked; after any "Cover text read abandoned" notice in the Console's `generation` category, the run instead paused with "Reading a book cover's text took too long. Bookworms tries again later." and saved no design for that book. **Stop Generating** then ends the run within a few seconds. During an idle run, the Spines tab's **Stop** and the **Stop Generating** item in the **Library** menu, the menu bar item, and the Dock icon's menu each end it, and no idle run starts again within the next few minutes.

Check the Hardcover sign-in on a signed iPhone without an iCloud library, following [Test Hardcover sign-in](../README-AI.md#test-hardcover-sign-in): the code flow completes through `api.hardcover.app/oauth2/device` and `api.hardcover.app/oauth2/token`, the library and its designs load, generation designs the phone's library, a sync about a week later, once the access token expires within the hour, renews the login without **Reconnect** (tests answer both endpoints with stubs, so only a real login shows that Hardcover serves them there and how it answers a renewal), **Reconnect** appears after the login is revoked, and **Sign out** removes the iPhone's copy of the library while the Library tab shows the copy in iCloud, and Hardcover's Authorized Apps page no longer lists Bookworms.

Check the shared library with development-signed builds on one iCloud account, signed in to the same Hardcover account. Tap **Sync now** on the Mac. Then open the app on an iPhone whose copy is at least four hours old, or on a new install, and check that **Last synced** shows the Mac's sync. On an Apple TV build with the shared-library work and **iCloud storage** on, check that the library the Mac synced appears without the Apple TV's own Hardcover fetch while it is less than a day old.
