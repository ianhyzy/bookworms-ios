# Bookworms iOS instructions

This independent repository implements Bookworms for iPhone and Mac from one target: spine generation for the Apple TV app, a 3D spine viewer, and share images. Follow the workspace `AGENTS.md` one folder up for writing, documentation, comments, and review rules.

- Target iOS 27 and later. The same target builds a native macOS 27 app for Apple silicon Macs: guard iOS-only APIs with `#if os(iOS)` or `#if os(macOS)`, add missing UIKit members to `Support/AppKitBridge.swift` instead of forking drawing code, and use `ThisDevice.name` in text that names the device. Use current SwiftUI, Swift concurrency with explicit isolation, and Swift 6 strict concurrency.
- Keep the companion read-only toward Hardcover. Its own Hardcover sign-in (OAuth device flow, read scopes only) stores its access and refresh tokens in this device's Keychain; never sync or upload them, and never write to Hardcover. Renew the login through `HardcoverAccount`, which lets only one request spend a refresh token.
- Each generation run designs with the best model tier available on this device when it starts (`ModelTier`, `BookAnalyzer.bestStatus(pcc:backup:onDevice:)`): Apple's `PrivateCloudComputeLanguageModel`; else the owner's backup model, a third-party provider (Anthropic, OpenAI, Google, or an OpenAI-compatible endpoint) chosen in Settings on the Mac or the Spines tab on the iPhone; else Apple's on-device `SystemLanguageModel`; else local defaults with no model, which choose families from the book's genres (`BookAnalyzer.genreFamilies(_:)`, mirroring the tvOS app's `BookWallLocalSpine.fontName(for:)`). Every tier keeps the same palette, `TitleLettering` ranking, font checks, and validation. Designs and series looks record their tier in `provenance` (Private Cloud Compute's record no model token; without one, the generator decides: `SpineDesignV1.modelToken`), and a run replaces a weaker tier's design or unedited look but never the reader's colors or edits. A local-defaults design whose font couldn't download records `font:system` (`SpineDesignV1.awaitsFont`) and ranks below its tier until a run reaches the font. `WorkLedger` records each check's tier, so a better tier rechecks those books on its first run; keep the tier read before the queue free of model requests. Private Cloud Compute without image input counts as unavailable, and a series copy never upgrades a look. Test builds compiled with `NO_PCC` (`script/install_on_device.sh`, `script/run_mac.sh`) never create the Private Cloud Compute model and start at the backup tier. Regenerate `Bookworms/SpineFontAtlas.lzfse` with `script/spine-font-atlas.sh` after changing `SpineFamily`.
- Backup providers plug in through FoundationModels' `LanguageModel` protocol (`Services/SpineDesigner.swift`), so add model features to the shared prompts and schemas rather than per provider. Keep provider API keys in this device's Keychain (`KeychainSecret`), never synced or uploaded; a remembered rejection (`SpineDesigner.rejection`) records only whether a key exists.
- Preserve the CloudKit JSON contract in `Bookworms/Models/CloudContract.swift`. It must stay compatible with the tvOS repository's `SpineCloudStore.swift`, and the tests pin the shared digests. The app also splices its Hardcover snapshot into the tvOS `CloudLibraryStore.swift` archive (`CloudLibraryArchive.splice(_:into:)`), which the Apple TV re-encodes through its own types: add a book or snapshot field to both apps together, and keep `LibraryArchiveTests`' copy of the tvOS types current. Keep the fixed-cover rule (`HardcoverClient.coverURLs`) and its test cases identical to the tvOS client's.
- Use `project.yml` and XcodeGen for project changes. Source folders are synced, so new files need no regeneration. Run Git commands inside this folder.
- Lint edited Swift with `xcrun swift-format lint --strict` and the repository `.swift-format`. Build with `script/build_and_run.sh`. Run tests when the request calls for them.
- Use the private preview library (`script/load-preview-data.py`) for Simulator checks. It contains real reading history: keep it in `.local/` and never publish screenshots made from it. Tests use fictional fixtures.
- Unsigned or Simulator builds prove compilation and local rendering only. iCloud access, push delivery, background scheduling, and Private Cloud Compute quotas need a signed device build.

## Before you push

Check each item that your change touches. These are the problems CodeRabbit finds most often here.

- **After an `await` or a delay,** recheck the state the action needs (the centered book, the mode, a presented sheet, the signed-in account) before acting. Capture values the result needs, such as the username in a share image, before the `await`. Cancel the task when its view or scene resets, and apply saves that can overlap, such as recolors, in the order the reader made them.
- **Sheets and hidden controls.** Present mutually exclusive sheets with one `.sheet(item:)` whose item is an enum, not two Booleans changed in one update. A control hidden with `.opacity(0)` also needs `.disabled(true)`.
- **Repeated work.** Don't sort or filter in `body` or in a property that `body` reads; compute once when the input changes. Requests read the cached credential (`HardcoverAccount.cachedCredential`), never the Keychain, and files decode off the main actor.
- **Hardcover tokens.** Only HTTP 400 or 401 with OAuth error `invalid_grant` ends a login. Keep the token for `invalid_client`, other OAuth errors, timeouts, and malformed replies. A request that joins a renewal falls back to the unexpired token, as the request that started it does.
- **Shared records.** When you splice or replace an Apple TV record, keep the fields this app doesn't model (`sources`, `isOwned`), and reject a malformed value instead of overwriting it. Filter Hardcover rows in the query (`status_id: {_neq: 6}`) before a row limit applies. A failed fetch is a failure, never an empty list.
- **Tests** use invented titles and names, write to their own `UUID`-named folders that `addTeardownBlock` or `defer` removes, and branch an assertion on `NO_PCC` when that flag changes the result.
- **Docs.** Search `README.md` and `docs/` for each name your change touches and correct every statement. Say "iPhone" or "Mac" when behavior differs, and state the settings and limits a checklist step assumes.
- **Both platforms compile.** When shared code changes, build for iOS (`script/build_and_run.sh`) and for the Mac (the `xcodebuild` command in `script/run_mac.sh`).

## CodeRabbit

- Before you open a pull request into `main`, run `coderabbit review --agent --base main` in the background (allow 15 minutes). Fix its Critical and Major findings and any useful Minor ones. Run it again on fix commits before you push them. Never pass `--use-credits`.
- CodeRabbit reviews a pull request once, when it opens; fix pushes don't start a review. Open pull requests ready for review, and don't merge while a review runs: merging cancels it.
- Critical and Major findings block a merge. Minor and Trivial findings never block testing, merging, or installs, but read each one, because the Minor label includes real bugs. Fix useful Minor findings in the same pull request; list any that need larger changes in a follow-up pull request. Fix a Trivial nitpick in the same pull request only when it's one line.
- When you decline a finding, reply in its thread with the reason. CodeRabbit can withdraw the finding and save the reason as a learning.
- Comment `@coderabbitai review` at most once per pull request, after a fix that changes credentials, a shared record, or concurrency, or that fixes a Critical or Major finding. Each review uses part of an hourly allowance.
