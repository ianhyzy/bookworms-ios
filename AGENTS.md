# Bookworms iOS instructions

This independent repository implements Bookworms for iPhone and Mac from one target: spine generation for the Apple TV app, a 3D spine viewer, and share images. Follow the workspace `AGENTS.md` (`~/Developer/BookwormsApps/AGENTS.md`, one folder up from the main checkout) for writing, documentation, comments, and review rules. Its Standing rules section holds the owner's rules for tests, review, merging, design sign-off, devices, and sessions; read it before you work in this checkout or in a worktree of it, because a worktree is outside the workspace folder.

- Target iOS 27 and later. The same target builds a native macOS 27 app for Apple silicon Macs: guard iOS-only APIs with `#if os(iOS)` or `#if os(macOS)`, add missing UIKit members to `Support/AppKitBridge.swift` instead of forking drawing code, and use `ThisDevice.name` in text that names the device. Use current SwiftUI, Swift concurrency with explicit isolation, and Swift 6 strict concurrency.
- Keep the companion read-only toward Hardcover. Its own Hardcover sign-in (OAuth device flow, read scopes only) stores its access and refresh tokens in this device's Keychain; never sync or upload them, and never write to Hardcover, except that **Sign out** revokes the companion's own login. Renew the login through `HardcoverAccount`, which lets only one request spend a refresh token.
- Each generation run designs with the best model tier available on this device when it starts (`ModelTier`, `BookAnalyzer.bestStatus(pcc:backup:onDevice:prefersBackup:)`): Apple's `PrivateCloudComputeLanguageModel`; else the owner's backup model, a third-party provider (Anthropic, OpenAI, Google, or an OpenAI-compatible endpoint) chosen in Settings on the Mac or the Spines tab on the iPhone; else Apple's on-device `SystemLanguageModel`; else local defaults with no model, which choose families from the book's genres (`BookAnalyzer.genreFamilies(_:)`, mirroring the tvOS app's `BookWallLocalSpine.fontName(for:)`). In builds with Private Cloud Compute, the per-device setting **Use this model instead of Private Cloud Compute** (`SpineDesigner.overridesPrivateCloudCompute`, off by default, ignored by `NO_PCC` builds) puts a backup model that is set up and not rejected before Private Cloud Compute. Every tier keeps the same palette, `TitleLettering` ranking, font checks, and validation. Designs and series looks record their tier in `provenance` (Private Cloud Compute's record no model token; without one, the generator decides: `SpineDesignV1.modelToken`), and a run replaces a design or unedited look only when it comes from local defaults or the on-device model and the run's tier is better (`ModelTier.isReplaced(by:)`): a Private Cloud Compute or backup design stays whichever model runs, and the reader's colors and edits always stay; only the reader's redesign or chosen cover replaces them, or a run at the tier whose model couldn't answer when another model designed the book in its place (`WorkLedger.Entry.standInFor`). A local-defaults design whose font couldn't download records `font:system` (`SpineDesignV1.awaitsFont`) and ranks below its tier until a run reaches the font. `WorkLedger` records each check's tier, so a better tier rechecks the books that local defaults or the on-device model last checked on its first run; keep the tier read before the queue free of model requests. Private Cloud Compute without image input counts as unavailable, and a series copy never upgrades a look. Test builds compiled with `NO_PCC` (`script/install_on_device.sh --no-pcc`, `script/run_mac.sh --no-pcc`) never create the Private Cloud Compute model and start at the backup tier; both scripts build with Private Cloud Compute by default. A model's reading of the cover alone decides which families a design may use (`BookAnalyzer.families(for:)`); a book's genres never override it and choose families only for local defaults. Regenerate `Bookworms/SpineFontAtlas.lzfse` with `script/spine-font-atlas.sh` after adding, removing, or renaming a `SpineFamily`.
- Backup providers plug in through FoundationModels' `LanguageModel` protocol (`Services/SpineDesigner.swift`), so add model features to the shared prompts and schemas rather than per provider. Keep provider API keys in this device's Keychain (`KeychainSecret`), never synced or uploaded; a remembered rejection (`SpineDesigner.rejection`) records only whether a key exists.
- Preserve the CloudKit JSON contract in `Bookworms/Models/CloudContract.swift`. It must stay compatible with the tvOS repository's `SpineCloudStore.swift`, and the tests pin the shared digests. The app also splices its Hardcover snapshot into the tvOS `CloudLibraryStore.swift` archive (`CloudLibraryArchive.splice(_:into:)`), which the Apple TV re-encodes through its own types: add a book or snapshot field to both apps together, and keep `LibraryArchiveTests`' copy of the tvOS types current. Keep the fixed-cover rule (`HardcoverClient.coverURLs`) and its test cases identical to the tvOS client's.
- Use `project.yml` and XcodeGen for project changes. Source folders are synced, so new files need no regeneration. Run Git commands inside this folder.
- Lint edited Swift with `xcrun swift-format lint --strict` and the repository `.swift-format`. Build with `script/build_and_run.sh`. Run the tests a change touches on a slim Simulator before it merges, without asking.
- Before a pull request merges, run `python3 script/premerge.py` on its head commit, and `python3 script/visual-check.py` when the change touches a view (`README-AI.md`, Pre-merge check and Visual check). The workspace's merge gate refuses `gh pr merge` without the pre-merge pass; it doesn't require the visual check.
- `ExampleProfile/` holds the owner's real reading history for **View example profile** (`script/export-example-profile.py`). Git ignores it apart from its placeholder: never commit it, print its contents, or load it in tests, and publish screenshots made from it only when the owner chooses his library for App Store screenshots (`docs/RELEASING.md`, Screenshots).
- Use the private preview library (`script/load-preview-data.py`) for Simulator checks. It contains real reading history: keep it in `.local/`, and publish screenshots made from it only under the same exception. Tests use fictional fixtures.
- Unsigned or Simulator builds prove compilation and local rendering only. iCloud access, push delivery, background scheduling, and Private Cloud Compute quotas need a signed device build.

## Before you push

Check each item that your change touches. These are the problems that reviews have found most often here.

- **After an `await` or a delay,** recheck the state the action needs (the centered book, the mode, a presented sheet, the signed-in account) before acting. Capture values the result needs, such as the username in a share image, before the `await`. Cancel the task when its view or scene resets, and apply saves that can overlap, such as recolors, in the order the reader made them.
- **Sheets and hidden controls.** Present mutually exclusive sheets with one `.sheet(item:)` whose item is an enum, not two Booleans changed in one update. A control hidden with `.opacity(0)` also needs `.disabled(true)`.
- **Repeated work.** Don't sort or filter in `body` or in a property that `body` reads; compute once when the input changes. Requests read the cached credential (`HardcoverAccount.cachedCredential`), never the Keychain, and files decode off the main actor.
- **Hardcover tokens.** Only HTTP 400 or 401 with OAuth error `invalid_grant` ends a login. Keep the token for `invalid_client`, other OAuth errors, timeouts, and malformed replies. A request that joins a renewal falls back to the unexpired token, as the request that started it does.
- **Shared records.** When you splice or replace an Apple TV record, keep the fields this app doesn't model (`sources`, `isOwned`), and reject a malformed value instead of overwriting it. Filter Hardcover rows in the query (`status_id: {_neq: 6}`) before a row limit applies. A failed fetch is a failure, never an empty list.
- **Tests** use invented titles and names, except the Discworld and House of Leaves tests, whose rules match real titles, write to their own `UUID`-named folders that `addTeardownBlock` or `defer` removes, and branch an assertion on `NO_PCC` when that flag changes the result.
- **Docs.** `README.md` is the owner's public overview: don't edit it. `README-AI.md` holds the technical reference. Search `README-AI.md` and `docs/` for each name your change touches and correct every statement. Say "iPhone" or "Mac" when behavior differs, and state the settings and limits a checklist step assumes.
- **Both platforms compile.** When shared code changes, build for iOS (`script/build_and_run.sh`) and for the Mac (the `xcodebuild` command in `script/run_mac.sh`).

## Review

- Before a pull request merges into `main`, run the `defect-review` and `slop-review` skills once on its diff. For a change to how the app looks, run them after the owner approves the design.
- High-severity findings block a merge. Lower findings never block testing, merging, or installs, but fix them, because they include real bugs: the small ones in the same pull request, and the larger ones in one follow-up pull request.
- Review again at most once, and only after a fix that changes credentials, a shared record, or concurrency, or that fixes a blocking finding. Put findings that appear later in the follow-up pull request, not in another round on the same one.
- When you decline a finding, give the reason in the pull request.
- The Standing rules section of the workspace `AGENTS.md` holds the full review and merge rules.
